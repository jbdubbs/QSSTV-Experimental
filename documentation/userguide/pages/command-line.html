Decode from file in the window

Choose File > Decode SSTV From File... (Ctrl+O) or the folder-with-a-note button on the Receive tab, then pick a recording. WAV, MP3, FLAC, OGG and AAC files are supported (any sample rate). The recording is played into the receiver at about ten times real time, you watch the picture appear, and afterwards the sound card receiver resumes. Decoded pictures are handled like any received picture. To decode a DRM recording, switch to the DRM settings tab first.

--decode

qsstv --decode recording.wav starts the program, opens the window and decodes the file. The --decode option may be repeated, and bare file names are treated as files to decode too, so you can also give qsstv one.wav two.wav. Add --drm for a DRM recording.

--batch (headless)

qsstv --batch -o out recording.wav decodes without a window, saves every picture found, prints the results and exits. Your settings are read but never written.

qsstv --batch --out-dir pictures/ pass1.wav pass2.mp3
qsstv --batch --mode PD120 --timeout 600 long-recording.flac
qsstv --batch --drm dsstv.wav

Pictures are named <file>_<n>_<MODE>.png in the output directory (the current directory by default). With --drm they are named <file>_<n>_drm.<ext> and a drm-stats: line (sync, FAC and MSC percentages, MSC flaps, FAC and MSC MER) is printed per file.

Exit codeMeaning
0Every file gave a picture.
1At least one file gave no picture.
2An unusable file or a bad option.
3Timeout.

The default timeout is the file's length plus 30 seconds; change it with --timeout. From the AppImage, run the AppImage file itself with the same options.

--listen (headless, sound card)

qsstv --listen -o pictures receives from the sound card without a window and saves every picture as it arrives, until you stop it. It is the live counterpart of --batch, for a receiver that runs unattended on a PC without a screen. Your settings are read but never written.

qsstv --list-devices
qsstv --listen --device "USB Audio" --out-dir pictures/
qsstv --listen --mode PD120 --timeout 3600 -o pictures/
qsstv --listen --drm -o dsstv/

The input is the one chosen in Options > Configuration > Sound, unless --device names another one for this run: --list-devices prints the inputs and the name can be shortened as long as it stays unique. A name that matches nothing (or several inputs) is refused with exit code 2 and the list, rather than quietly using the default. A saved “input from file” or “record to file” setting is ignored. --mode and --drm work as with --batch.

Pictures are named like the ones the window saves, <MODE>_<date>_<time>.png (UTC, for example PD120_20261023_194707.png), in the output directory (the current directory by default). With --drm they are named drm_<date>_<time>.<ext>. For each picture one line is printed on the standard output, <input> -> <file> (<MODE>, <width>x<height>); messages go to the standard error.

The run goes on until you press Ctrl+C or send SIGTERM (or SIGHUP), or until --timeout seconds have passed. A picture that is still being received when it stops is saved too, if it passes the limit described below (analog SSTV; a second Ctrl+C ends the program at once). If the sound input cannot be opened, or disappears while running (a USB sound card is unplugged, for example), the program says so and exits with code 2, so a service manager can start it again.

As in the window, an interrupted or poorly received analog picture is only kept if at least Save if Complete (%) of its lines arrived (25 by default; see Receiving), so a noisy channel does not fill the disk with fragments. --listen and --batch read this setting, like the others, from the settings you saved in the window, and --min-complete <percent> overrides it for one run (0 to 100; 100 keeps only pictures that arrived in full). It applies to the picture that is cut off when you stop as well, and never changes the saved setting. DRM files are not affected: they are saved only when complete.

Exit codeMeaning
0Stopped with Ctrl+C or a signal, or the --timeout ended the run after at least one picture.
1The --timeout ended the run and no picture was received.
2A bad option, an unknown --device, or a sound input that could not be opened or was lost.

--encode

qsstv --encode picture.png --mode PD120 --wav-out picture.wav converts a picture into the SSTV audio for the chosen mode, through the normal transmit path, and writes it to a WAV file; no sound card is used. The default output name is <image>.wav. As with --batch, your settings are read but never written. The EXIF or HEIF orientation of a photo is applied, as when you open it on the Transmit tab. Add --drm to make a DRM transmission instead; then --drm-mode, --drm-bw, --drm-qam, --drm-prot, --drm-interleave, --drm-rs, --drm-size and --drm-encoding choose the parameters (otherwise your Transmit-tab settings are used).

qsstv --encode rose.png --mode PD120 --wav-out pd120.wav
qsstv --encode rose.png --drm --drm-mode B --drm-qam 16 --drm-bw 2.8 --wav-out rose-drm.wav

A round trip is a good test of an installation: encode a picture and then decode the WAV with --batch.

--render-template and --convert-template

Two headless options for the templates used on the Transmit tab (Transmit). Neither starts the receiver or opens a window.

qsstv --render-template cq.templ --template-var m=N0CALL lays the template over a picture exactly as the transmit path does and saves the result as cq.templ.png (change that with --template-out). Without --template-base the template is laid over a gray frame the size of the template; --template-size WxH scales the picture to a mode's size first (for example 320x256), and --template-replay fills the template's replay slot. --template-var sets the text macros: c=W1AW replaces %c (repeatable; a macro you do not set expands to nothing).

qsstv --render-template bath.templ --template-size 320x256 --template-var c=W1AW --template-out preview.png
qsstv --render-template cq.qtempl --template-base rose.png --template-var m=N0CALL
qsstv --render-template here.qtempl --template-var a=47.6062 --template-var b=-122.3321 --template-var g="Seattle, WA"

The latitude, longitude and place macros are %a, %b and %g; the command line neither reads a GPS nor looks up a place, so give them yourself. They are printed exactly as given, in whatever notation, for example --template-var a="47 36.37N".

qsstv --convert-template cq.templ writes the same template in the native .qtempl format next to the original (or to --template-out). The original is not touched. Both formats can be used in the templates folder; the .templ files made by QSSTV 9.x and by earlier versions of this program keep working. A file that is damaged or is not a template is refused with exit code 2 and never crashes the program.

Other options

--list-modes
Prints the short names accepted by --mode, with the full names (see SSTV modes).
--mode <mode>
With --batch, --listen or --decode: receive only this mode instead of auto detection. With --encode: the mode to transmit.
--install / --uninstall
AppImage only: add or remove the desktop menu entry and icons, then exit. See Help menu, updates and desktop integration.
--min-complete <percent>
With --batch or --listen: keep an analog picture only if at least this percentage of its lines was received, instead of the Save if Complete (%) setting (25 by default). Use it to keep fragments of weak signals out of the output directory.
--list-devices
Prints the sound card inputs that --device accepts, one per line (the default input is marked), and exits.
-h, --help and -v, --version
Print the help or the version and exit.
--rx-gain <dB>, --rx-noise <dBFS>
Test aids for --batch: amplify or attenuate the recording, or add white noise of a given level (for example -40), before the receiver.
